Methodology

Each experiment applies a targeted code mutation to one module, then runs identical inputs against the baseline and changed versions. The harness compares return values, exceptions, refusal rules, refusal reasons, and resolved paths. Evidence is classified into four levels: STATIC_SUSPICION (module is imported but no runtime path proven), RUNTIME_REACHABLE (code ran, no behavioural change), BEHAVIOURAL_CHANGE (output differs but decision unchanged), and FAILURE_PROPAGATION (decision changed, CLI exit code or hook block affected). The existing test suite is run against each mutation to determine whether it would have caught the regression. Where evidence is unavailable, UNKNOWN is returned.
